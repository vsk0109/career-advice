# API Specification (FastAPI)

Base URL (local dev): `http://localhost:8000`
Interactive docs auto-generated by FastAPI at `/docs` — use this during dev and demo it to judges as a bonus.

---

### `POST /profile`
Save a student's intake data.

**Request body:**
```json
{
  "name": "Vaishnavi Sudarsan K",
  "interests": ["technology", "design"],
  "hobbies": ["reading", "coding", "sketching"],
  "riasec_answers": [4, 2, 5, 3, 1, ...],
  "academics": {"Math": 85, "Physics": 78, "English": 65},
  "self_rated_skills": {"communication": 4, "coding": 5, "leadership": 2}
}
```

**Response:**
```json
{
  "student_id": "uuid",
  "riasec_scores": {"R": 3, "I": 8, "A": 5, "S": 2, "E": 4, "C": 6}
}
```
Backend computes `riasec_scores` from `riasec_answers` server-side (don't trust the client to compute this).

---

### `GET /profile/{student_id}`
Returns the saved profile as stored (same shape as above response, plus original intake fields).

---

### `GET /careers`
Returns the full curated career list (for browsing/debugging, not shown raw in main UI).

**Response:** array of career objects (see `02b_DATA_MODEL.md` shape).

---

### `POST /score`
Given a student_id (or a full profile inline), returns ranked career matches.

**Request body:**
```json
{ "student_id": "uuid" }
```

**Response:**
```json
{
  "top_matches": [
    {
      "career": "Data Scientist",
      "score": 87.4,
      "riasec_match": 91.0,
      "academic_fit": 85.5,
      "interest_overlap": 80.0,
      "skill_score": 70.0,
      "skill_gaps": ["Machine Learning", "Statistics"],
      "courses": [...],
      "colleges": [...],
      "scholarships": [...],
      "certifications": [...]
    },
    { "career": "..." }
  ]
}
```

---

### `POST /score/insights`
Given the `/score` output, calls the LLM to generate explanation text + roadmap. Split from `/score` so the deterministic ranking is fast and testable independently of the (slower, less reliable) LLM call. The generated roadmap for the top match is persisted to `roadmap_steps` (see `GET /roadmap/{student_id}`).

**Request body:**
```json
{ "student_id": "uuid", "top_matches": [ /* from /score */ ] }
```

**Response:**
```json
{
  "explanations": {
    "Data Scientist": "This fits you because...",
    "...": "..."
  },
  "roadmap": [
    "Step 1: Take an introductory Statistics course this semester.",
    "Step 2: Build a small data analysis project using Python.",
    "Step 3: Earn a beginner certification in Data Analytics."
  ],
  "emerging_trend": "AI-augmented data analysis roles are growing fast in..."
}
```
If the LLM call fails, return a graceful fallback (see `02_ARCHITECTURE.md` — fallback strategy), never a 500 that breaks the dashboard.

---

### `POST /mentor/chat`
Chat-based mentor, uses profile + top matches as context. Persists both the
student's message and the AI reply to `mentor_chat`, and includes the last
6 turns of prior conversation as context for the LLM.

**Request body:**
```json
{
  "student_id": "uuid",
  "message": "Which is better, Data Science or Software Engineering, for someone who likes both math and building things?"
}
```

**Response:**
```json
{ "reply": "Given your strong Math and Investigative + Realistic personality profile, ..." }
```

---

### `GET /mentor/chat/{student_id}`
Returns the full chat history for a student, oldest first.

**Response:**
```json
{
  "messages": [
    { "sender": "student", "message": "...", "created_at": "2026-08-11T20:00:00" },
    { "sender": "ai", "message": "...", "created_at": "2026-08-11T20:00:02" }
  ]
}
```

---

### `GET /roadmap/{student_id}`
Returns the student's roadmap steps (across all careers they've generated
insights for), with completion status. Roadmap steps are created by
`POST /score/insights` — each call replaces the stored roadmap for that
student+career with the freshly generated one.

**Response:**
```json
{
  "steps": [
    { "step_id": 1, "career": "Data Scientist", "step_number": 1, "description": "Step 1: ...", "completed": false }
  ]
}
```

---

### `PATCH /roadmap/{student_id}/steps/{step_id}`
Marks a roadmap step complete/incomplete.

**Request body:**
```json
{ "completed": true }
```

**Response:** the updated step, same shape as in `GET /roadmap/{student_id}`.

---

## Error Handling Convention
All errors return:
```json
{ "detail": "human-readable message" }
```
using FastAPI's standard `HTTPException`. Use proper status codes (400 for bad input, 404 for missing student/career, 502 for upstream LLM failure).
