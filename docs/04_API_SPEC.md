# API Specification (FastAPI)

Base URL (local dev): `http://localhost:8000`
Interactive docs auto-generated by FastAPI at `/docs` — use this during dev and demo it to judges as a bonus.

**Auth:** every endpoint except `/auth/signup`, `/auth/login`, and `GET /careers`
requires `Authorization: Bearer <token>`, where `<token>` is the `access_token`
returned by signup/login. The student is identified entirely by this token —
no endpoint accepts a `student_id` from the client.

---

### `POST /auth/signup`
Creates a student account with an empty profile (filled in later via
`POST /profile`). `email` must be unique.

**Request body:**
```json
{ "name": "Vaishnavi Sudarsan K", "email": "vaishnavi@example.com", "password": "at least 8 chars" }
```

**Response:**
```json
{
  "student_id": "1",
  "name": "Vaishnavi Sudarsan K",
  "email": "vaishnavi@example.com",
  "access_token": "eyJ...",
  "token_type": "bearer"
}
```
`409` if the email is already registered.

---

### `POST /auth/login`

**Request body:**
```json
{ "email": "vaishnavi@example.com", "password": "..." }
```

**Response:** same shape as `/auth/signup`. `401` on wrong email/password.

---

### `POST /profile`
Save the authenticated student's intake data (RIASEC answers, academics,
interests, hobbies, skills). Overwrites any previously saved intake.

**Request body:**
```json
{
  "interests": ["technology", "design"],
  "hobbies": ["reading", "coding", "sketching"],
  "riasec_answers": [4, 2, 5, 3, 1, ...],
  "academics": {"Math": 85, "Physics": 78, "English": 65},
  "self_rated_skills": {"communication": 4, "coding": 5, "leadership": 2}
}
```

**Response:**
```json
{
  "student_id": "1",
  "name": "Vaishnavi Sudarsan K",
  "email": "vaishnavi@example.com",
  "riasec_scores": {"R": 3, "I": 8, "A": 5, "S": 2, "E": 4, "C": 6},
  "interests": ["technology", "design"],
  "hobbies": ["reading", "coding", "sketching"],
  "academics": {"Math": 85, "Physics": 78, "English": 65},
  "self_rated_skills": {"communication": 4, "coding": 5, "leadership": 2}
}
```
Backend computes `riasec_scores` from `riasec_answers` server-side (don't trust the client to compute this).

---

### `GET /profile`
Returns the authenticated student's saved profile, same shape as the `/profile` POST response. Empty `riasec_scores`/`academics`/etc. means the student hasn't completed intake yet.

---

### `GET /careers`
Returns the full curated career list (for browsing/debugging, not shown raw in main UI). No auth required.

**Response:** array of career objects (see `02b_DATA_MODEL.md` shape).

---

### `POST /score`
Returns ranked career matches for the authenticated student. No request body.

**Response:**
```json
{
  "top_matches": [
    {
      "career": "Data Scientist",
      "score": 87.4,
      "riasec_match": 91.0,
      "academic_fit": 85.5,
      "interest_overlap": 80.0,
      "skill_score": 70.0,
      "skill_gaps": ["Machine Learning", "Statistics"],
      "courses": [...],
      "colleges": [...],
      "scholarships": [...],
      "certifications": [...]
    },
    { "career": "..." }
  ]
}
```
`404` if the student hasn't completed intake yet.

---

### `POST /score/insights`
Given the `/score` output, calls the LLM to generate explanation text + roadmap. Split from `/score` so the deterministic ranking is fast and testable independently of the (slower, less reliable) LLM call. The generated roadmap for the top match is persisted to `roadmap_steps` (see `GET /roadmap`).

**Request body:**
```json
{ "top_matches": [ /* from /score */ ] }
```

**Response:**
```json
{
  "explanations": {
    "Data Scientist": "This fits you because...",
    "...": "..."
  },
  "roadmap": [
    "Step 1: Take an introductory Statistics course this semester.",
    "Step 2: Build a small data analysis project using Python.",
    "Step 3: Earn a beginner certification in Data Analytics."
  ],
  "emerging_trend": "AI-augmented data analysis roles are growing fast in..."
}
```
If the LLM call fails, return a graceful fallback (see `02_ARCHITECTURE.md` — fallback strategy), never a 500 that breaks the dashboard.

---

### `POST /mentor/chat`
Chat-based mentor, uses the authenticated student's profile + chat history as
context. Persists both the student's message and the AI reply to
`mentor_chat`, and includes the last 6 turns of prior conversation as
context for the LLM.

**Request body:**
```json
{ "message": "Which is better, Data Science or Software Engineering, for someone who likes both math and building things?" }
```

**Response:**
```json
{ "reply": "Given your strong Math and Investigative + Realistic personality profile, ..." }
```

---

### `GET /mentor/chat`
Returns the authenticated student's full chat history, oldest first.

**Response:**
```json
{
  "messages": [
    { "sender": "student", "message": "...", "created_at": "2026-08-11T20:00:00" },
    { "sender": "ai", "message": "...", "created_at": "2026-08-11T20:00:02" }
  ]
}
```

---

### `GET /roadmap`
Returns the authenticated student's roadmap steps (across all careers
they've generated insights for), with completion status. Roadmap steps are
created by `POST /score/insights` — each call replaces the stored roadmap
for that student+career with the freshly generated one.

**Response:**
```json
{
  "steps": [
    { "step_id": 1, "career": "Data Scientist", "step_number": 1, "description": "Step 1: ...", "completed": false }
  ]
}
```

---

### `PATCH /roadmap/steps/{step_id}`
Marks a roadmap step complete/incomplete. `404` if `step_id` doesn't belong to the authenticated student.

**Request body:**
```json
{ "completed": true }
```

**Response:** the updated step, same shape as in `GET /roadmap`.

---

## Error Handling Convention
All errors return:
```json
{ "detail": "human-readable message" }
```
using FastAPI's standard `HTTPException`. Status codes: `401` missing/invalid/expired token, `404` missing student/career/step, `409` duplicate signup email, `400` bad input, `502` upstream LLM failure.
